# Solver catalog manifests

Ultra-Fast WBPP does not treat an installed solver executable as proof that a suitable catalog exists. Catalogs and Astrometry.net index sets are versioned artifacts with separate storage, coverage, license, citation, and integrity requirements.

An application-managed download is enabled only when every artifact has an HTTPS URL, exact byte count, SHA-256, storage scope, citation, and a versioned provider-terms notice. `user-download-required` means that Ultra-Fast WBPP does not bundle or redistribute the data: it may fetch the immutable file directly from the provider only after the user supplies the exact acceptance ID displayed by `catalog list`. That acknowledgement records responsibility for the direct download; it is not a license grant or a claim that Ultra-Fast WBPP has resolved the provider's data terms.

The checked 4107–4112 manifest records the official byte counts, provider MD5 values, independently computed SHA-256 values, quad scales, and derived field-of-view guidance. Astrometry.net recommends quads spanning roughly 10%–100% of image width, so selecting by FOV is guidance rather than a promise that a particular field will solve. The complete six-file set needs 349,692,480 bytes (333.5 MiB), before temporary download space.

Downloads are resumable in the application-owned `.downloads` directory only with an unchanged strong ETag and strict `Range`/`If-Range` response. Exact HTTPS URLs and manifest origins are enforced; redirects, localhost/IP origins, oversize streams, and mixed-object ranges fail closed. A file becomes visible to the solver only after size and SHA-256 validation followed by create-only atomic publication. `astrometry.cfg` and an immutable `installed-set-*.json` receipt are written next to the indexes. The receipt binds source URLs, relative paths, sizes and hashes to the exact manifest digest and records transport ETag evidence separately from its scientific byte identity; a future solver receipt can use `installed_set_identity_for_solver_indexes()` to bind Astrometry.net's `INDEXID` evidence to those actual local bytes.

The checked-in ASTAP manifest intentionally has no direct artifact URL or hash because the database variant and data redistribution terms have not been selected. The GUI may guide the user to the official page and validate a chosen directory, but it cannot silently download a moving or unverified archive.

Primary references: [Astrometry.net index selection guide](https://astrometry.net/doc/readme.html#getting-index-files), [official 4100-series directory](https://data.astrometry.net/4100/), [4100-series build notes](https://data.astrometry.net/4100/README), and [provider MD5 list](https://data.astrometry.net/4100/md5sums.txt). The provider documentation says index files have separate license conditions but does not currently supply enough information here to claim redistribution rights; the manifests therefore remain conservatively marked `provider-specific-unresolved`.
