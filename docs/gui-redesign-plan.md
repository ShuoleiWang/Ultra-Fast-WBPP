# 桌面端 GUI 重设计方案

状态：已实现（2026-09-19 夜，见 §8）。目标：让 Ultra-Fast WBPP 的原生 macOS 应用具有 Apple 级的审美与手感，同时不改变引擎契约（只读来源、只新建结果、可审计决定）。配套高保真原型：https://claude.ai/artifact/Eo5a28veF8pVtC564jiNbA （四个视图：帧列表、检视器、处理中、结果；浅色/深色可切换）。

## 1. 现状诊断（对照 `apps/desktop/src/App.tsx`、`styles.css` 与 `assets/branding/` 截图；截图摄于 2026-09-05/08，早于 `db4271f` 的一步式流程改版，但视觉语言未变）

| 现象 | 为什么不像 Apple |
|---|---|
| 带编号的向导头（现为 导入 / 处理 / 结果 三步，只有"导入"可点回） | 原生 mac 应用几乎不用向导条；流程由侧栏、工具栏与内容区的状态表达 |
| 只有浅色（`styles.css:13` 钉死 `color-scheme: light`），Tauri 未设 `theme`、无 vibrancy、无应用菜单 | mac 用户默认期待随系统的深色模式、侧栏材质与标准菜单（⌘O 导入、⌘, 设置） |
| 虚线拖放区 + 蓝色实心按钮 + 圆角卡片套卡片 | 这是 Web SaaS 的语汇；mac 用材质（vibrancy）、细分隔线（hairline）、系统控件、留白来分层 |
| 品牌蓝 `--blue #0066cc` 用于徽标、步骤圆点、活动标签、进度环与主按钮，`--line #8e8e93` 深灰边框包住表格、输入框与面板 | Apple 的强调色只出现在可交互元素与选中态；分层靠 hairline（29% 透明的分隔线）与材质，而不是深灰实线框 |
| 大号说明文字、重复的免责声明（"Sources stay read-only…" 出现两次） | HIG：一句话说清，其余放进帮助与检视器；界面不是文档 |
| `HARD_FAIL`、`POLICY e9ad7200e0e1`、`content-bound` 等内部术语直接可见 | 面向人的措辞：排除 / 需确认 / 通过；技术细节折叠到检视器 |
| 表格是网页表格，缩略图小且被文字包围 | 数据密度与图像应像 Photos/Finder：行高一致、缩略图为主角、元数据用 secondary 色 |
| 页脚横幅（版本号 · QC4 · 免责声明）、Legal 弹出、语言下拉常驻顶栏 | 这些属于"关于"窗口、菜单栏与设置，不该占内容区 |
| 处理页只有一个进度环 + 阶段列表，没有日志；结果页用装饰性星野插画占半屏 | 进度应在工具栏活动区常驻，内容区留给可操作的东西；结果页的主角是 master 预览与质量数字 |
| 检视/证据以卡片列表形式铺满页面，每帧一张卡，PASS 帧也占位 | 列表 + 检视器：一行一帧，选中才展开细节；通过的帧不制造噪音 |

## 2. 设计原则

1. **一个窗口，一个对象**：一个"项目"= 一批来源 + 一份配方 + 一次结果。窗口就是项目文档（像 Numbers/Logic），没有向导。
2. **系统语汇**：SF 字体、系统控件、侧栏材质、hairline、8 pt 网格、系统强调色，暗色模式与 macOS 同步。
3. **内容优先**：帧缩略图与 master 预览是第一公民；文字降为标签与次要信息；解释放进检视器与帮助。
4. **状态可见，不打断**：筛片决定、处理进度、错误都在原位显示（badge、进度条、行内提示），不弹向导，不要求点击才能继续。
5. **可审计但不啰嗦**：每个决定可展开看证据与反事实数字（对应筛片方案的审计报告），默认收起。

## 4. 信息架构与布局

```
┌ 工具栏（titleBarStyle Overlay，交通灯左侧，标题居中：项目名 · 61 帧）───────────────┐
│ [导入 ▾] [筛片 ▾] [配方 ▾]        ◉ 处理进度/状态（活动区）        [搜索]  [检视器] │
├ 侧栏 240 ─────┬ 内容区 ───────────────────────────────────────┬ 检视器 300（可折）┤
│ 来源            │ 分段控件：表格 | 网格                           │ 选中对象的详情    │
│  ▸ 光帧 61      │ 帧列表：缩略图 · 文件名 · 目标/滤镜 · 曝光 ·    │  缩略图（大）     │
│    NGC 7331 L   │        夜 · 星数 · FWHM · 透明度 · 决定 badge   │  头信息           │
│    NGC 7331 R … │ 过滤条：全部 / 通过 / 降权 / 排除 / 需确认      │  筛片证据与       │
│  ▸ 平场 20      │                                                  │  反事实数字       │
│  ▸ 暗场（主）   │ 底部状态条：已选 3 / 61 · 4 夜 · 有效曝光 5.1 h │  [仍然包含][排除] │
│  ▸ 偏置（主）   │                                                  │                   │
│ 结果            │                                                  │                   │
│  ▸ 本次运行     │                                                  │                   │
└────────────────┴──────────────────────────────────────────────┴───────────────────┘
```

- **导入**：整个窗口接受拖放，拖入时内容区显示半透明覆盖层"松开以加入 N 个文件"；也可从工具栏"导入 ▾"或 ⌘O。角色由 header 自动识别，只有冲突才在行内出现黄色 badge 与修正下拉。
- **筛片**：不再是独立页。列表中的"决定"列即结果（通过 / 降权 0.6× / 排除 / 需确认），过滤条可切换；检视器展示理由（人话）与证据（可展开），以及"仍然包含 / 排除"两个覆盖开关（保持 hash 绑定，但不再阻塞流程）。
- **配方与处理**：工具栏"配方 ▾"是弹出面板（优先级：深度/平衡/分辨率；输出目录；高级折叠）。主按钮"处理"在工具栏右侧；点击后活动区出现阶段进度（导入 → 定标 → 配准 → 归一化 → 积分 → 解算 → 发布），可点开看日志。
- **结果**：侧栏"结果"项；内容区为 master 网格（每个滤镜一张卡：预览、FWHM、深度、背景平坦度与 PI 对照的通过/警告），点击进大图；工具栏动作"在 Finder 中显示""导出报告"。
- **设置**：⌘, 打开标准设置窗口：语言、求解器与星表、性能档、诊断包导出。

## 5. 组件规范

- 侧栏：Source List 风格，行高 28，图标 16 pt，计数右对齐 secondary 色；分组标题 11 pt 大写 letter-spacing .06em。
- 表格：可排序列头 11 pt secondary；行 36 pt 含 48 px 缩略图（4 pt 圆角）；斑马纹用 `--surface` 与 3% 叠加；选中行用 accent 10% 填充，不用边框。
- Badge：胶囊，11 pt semibold，底色为状态色 12% 透明度、文字为状态色；"通过"不显示 badge（只显示点），减少噪音。
- 控件：系统 `<button>`/`<select>` 样式重置为 macOS 外观（高 22/28 pt，6 pt 圆角，主按钮 accent 填充白字，次按钮白底 hairline）。
- 检视器：Form 风格，标签右对齐 secondary、值左对齐；证据用可展开的 disclosure；反事实数字用表格 `tabular-nums`。
- 空状态：内容区中央一枚 SF 风格线性图标 + 一句话 + 主按钮，不用虚线框。
- 进度：工具栏活动区 200 px 细进度条 + 阶段文字；完成后变为绿色对勾 2 s 后淡出。

## 6. 实现路径（React + Tauri 2，不换框架）

1. `styles.css` 重写为令牌 + 组件层（约 600 行替换 1862 行），去掉页脚与向导条；`prefers-color-scheme` 与 Tauri `theme` 同步。
2. 布局：`App.tsx` 拆为 `Toolbar`、`Sidebar`、`FrameTable`、`Inspector`、`ResultsGrid`、`ProgressActivity`；状态仍由 `useWorkflow.ts` 提供（不改引擎桥接协议）。
3. Tauri：保持 `titleBarStyle: Overlay`；新增 `window-vibrancy`（macOS `Sidebar` 材质，仅侧栏容器透明）；`macOSPrivateApi: false` 不需要；Windows 沿用 Mica/纯色降级。
4. 图标：内联 SVG 按 SF Symbols 的 1.5 px 线宽与 16/20 pt 尺寸重绘 12 个常用符号（导入、筛片、配方、处理、结果、检视器、通过、警告、排除、Finder、导出、搜索）。
5. 文案：i18n 表按"面向人的措辞"重写，技术码保留在检视器的证据行；中英两套同步。
6. 测试：`App.test.tsx`/`NativeApp.test.tsx` 中与流程相关的断言保留（导入 → 决定 → 处理 → 结果），替换与向导编号/审批按钮文案绑定的选择器。
7. 分两步交付：先令牌与布局（一周），再检视器与结果页（一周）；每步都用截图对比 HIG 清单（对齐、间距、对比度 ≥ 4.5:1、暗色模式）。

## 6a. 重构时必须保留的行为（来自 `App.test.tsx` / `NativeApp.test.tsx` 的断言）

- 两条入口都存在：导入 → 可选筛片检视 → 开始，以及导入 → 直接开始；不检视时 `reviewSelections` 为空数组且不调用 `inspectQuality`。
- 结果页有名为"筛片结果"的 region，显示 `{admitted} 张进入叠加 · {excluded} 张排除`、帧名、证据（`; ` 连接）、复核预览 `<img>`（alt `{name} 的复核预览`，`src` 为 `previewDataUrl`）。
- 已有筛片结果重开不重跑；重新导入 Light 才失效。
- 顶栏 `data-tauri-drag-region="deep"`，语言选择器 `="false"`；运行中步骤按钮禁用，双击开始只启动一次。
- 进度：`aria-label` 为纯 `"22%"` 字符串；阶段 `<li>` 类名 `waiting/running/done/failed`；总进度单调且在完成前钳在 99%。
- 计时器 `role="timer"`：运行中名为"已用时间"，结束后"总用时"，取消/失败冻结，新项目归零。
- REVIEW 审批：单面板、`sha256:` 64 位摘要、策略摘要、有预览才可批准；批准是开关，发送 `{sourceSha256, gatePolicyDigest}`；每个目标×滤镜至少 2 张才可开始，阻塞句精确。
- 校准高级设置默认折叠、不显示 SHA、字段留空不臆造；未保存的编辑禁用开始。
- 语言切换持久化到 `localStorage`，抛异常时回退英文；`document.documentElement.lang` 同步。
- 结果页的"最终门禁 · WCS 已解算"只在 `onComplete` 通过门禁后出现；产品按钮"在 Finder 中显示 {name}" 调用 `revealOutput(path)`。
- 无障碍：skip link、landmark roles、`aria-current/pressed/expanded`、3 px 焦点环、`prefers-reduced-motion`。

重设计只改视觉与布局，这些语义（roles、名称、状态机）原样保留；把"批准"改为"仍然包含"只是文案，机制不变。筛片方案落地后，审批语义再随 `unattended-v1` 调整。

## 7. 非目标

- 不做全屏营销式首页、不做玻璃拟态大面积模糊、不引入重型 UI 库（保持零依赖的 React）。
- 不改变引擎的"只读来源 / 只新建结果 / 可审计"契约与 hash 绑定的覆盖机制。

## 8. 实现记录（2026-09-19）

- 结构：`App.tsx` 拆为 `Toolbar`（导入动作、文档标题/运行活动区、语言、检视器开关）、`Sidebar`（项目三态、来源分组、结果）、内容视图 `views.tsx`（导入空态与素材表、筛片表格与目标×滤镜矩阵、处理阶段、结果主图卡片与产品）、`Inspector`（选中帧证据 + 校准/筛片检查）、底部 `LaunchBar`（输出位置与开始）。状态机 `useWorkflow.ts` 与引擎桥接协议未改。
- 视觉：`styles.css` 重写为令牌 + 组件层（约 480 行替换 1862 行），浅色/深色随系统；hairline 分层、系统强调色只用于控件与选中；`icons.tsx` 按 SF Symbols 风格重绘；品牌标志 `BrandMark` 与应用图标由 `apps/desktop/scripts/brand_icon.py` 生成（Pillow，可复现），`assets/branding/openastroflow-icon-1024.png` 与 `src-tauri/icons/` 同步更新。
- 契约：`App.test.tsx` / `NativeApp.test.tsx` 全部保留且不改断言（57 项通过）；向导条被侧栏取代但 `nav[aria-label=处理流程]` 与 导入/处理/结果 语义仍在；审批按钮文案暂未改为"仍然包含"（待筛片策略在桌面端接入时一并调整）。
