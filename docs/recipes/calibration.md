# Light, Flat, Dark, and Bias calibration

Ultra-Fast WBPP accepts raw calibration frames or already integrated masters. When Bias is needed, use either raw Biases or exactly one MasterBias. The desktop standard workflow can omit separate Bias when matching bias-inclusive Darks cover every raw target. Raw and master Flats/Darks may coexist only when they serve disjoint filter/exposure profiles; a Light that matches both modes, or more than one supplied master, blocks planning.

Within one ordinary single-field E2E run, raw Bias/Dark/Flat masters are built once for registration and then reused by the final pixel pipeline through a private content-bound handoff. This is not the user-supplied-master path: the handoff binds every source, generated master, Dark bias semantics, Flat application scale, and upstream receipt, and fails closed on drift. The raw-rebuild oracle must remain pixel-identical before this optimization is accepted for another execution mode.

For a matched-exposure Dark that includes bias, the Light operation is `Light - MasterDark`; subtracting MasterBias again would double-remove the pedestal. Raw Flats use an exact-exposure, temperature-compatible bias-inclusive Dark/Flat-Dark when present, otherwise the matched Bias, before normalization and robust integration. Dark scaling is not inferred silently. Every master records input identities, combine/rejection parameters, finite-pixel statistics, normalization, and checksum.

Additive Bias/Dark calibration also requires an explicit numeric-domain contract. Unsigned camera FITS inputs derive their zero-based sensor-code extent from `BITPIX`, `BSCALE`, and `BZERO`; a nonzero physical lower endpoint is currently rejected. Float XISF inputs are accepted as normalized samples only when the XISF image metadata explicitly declares finite `bounds="0:1"` (equivalent decimal spellings are accepted). Thus a normalized PixInsight Float32 MasterDark is multiplied by the Light's sensor-code extent before subtraction, while a raw-built MasterDark already in the Light domain retains application scale 1. The registration preview and full pixel pipeline consume the same resolved scales, and receipts record storage evidence, normalized-unit scale, authority, and each additive application scale. A Float FITS additive master is ambiguous unless its exact SHA-bound override declares `numericDomain` and `normalizedUnitScale`; file extension, dtype, and observed pixel range are never used to guess units.

A supplied MasterBias, MasterDark, or MasterFlat is opened read-only, content-hashed, and used directly. It is never integrated or calibrated a second time. A non-unit MasterFlat is normalized only in the Light application expression, `(Light - calibration) / MasterFlat * robustMedian(MasterFlat)`; the caller's file is unchanged. In the desktop standard workflow, an otherwise undeclared MasterDark follows the usual bias-inclusive convention. Explicit header declarations or a sparse advanced `biasIncluded:false` override identify a bias-subtracted Dark, which also needs a matching Bias. `strict-v1` retains the older explicit-declaration requirement. File hashes remain internal identity checks, not a user confirmation step.

The desktop uses `mono-standard-v1`: valid roles and image geometry are required, known camera/gain/offset/binning/readout conflicts are rejected, and unrecorded acquisition fields stay unknown. Flat requires the matching filter. Dark requires matching exposure (absolute tolerance `1e-6` seconds); known temperatures must be within 3°C, while missing Dark temperature is explicitly unverified. No Dark scaling is silently introduced. This is a declared processing convention, not proof of unrecorded metadata.

Old CLI recipes default to `strict-v1`, which still requires positive evidence for the full acquisition profile. Select [mono-standard.json](mono-standard.json) with `--recipe` to use desktop conventions.
Lights of the same filter may contain multiple exposure lengths. Each Light uses its own exact-exposure Dark for both registration preview calibration and full-resolution calibration. Before same-filter integration, calibrated pixels are scaled linearly to the shortest admitted exposure in that filter; the receipt records every source exposure, each scale, the reference exposure, and the summed integration time. Single-exposure groups retain scale 1.0.

Calibration is tiled to stay within the detected memory budget. A recipe cannot select a concurrency/tile combination whose estimated peak exceeds the reserved fraction of unified or system memory.

In standard mono, missing Bayer metadata follows the selected monochrome mode; an explicit Bayer pattern (RGGB, BGGR, GRBG, GBRG) selects the one-shot-colour path, in which the master flat is applied with separate scaling factors per colour channel (see [OSC / CFA](osc-cfa.md)). Normal PI XISF masters therefore do not need a per-file form or values copied from Lights. Advanced overrides are sparse: omitted fields do not replace file metadata, and a real numeric zero remains distinct from an unrecorded value. Numeric units are still validated before additive subtraction. See [XISF pixels and LocalNormalization](xisf-and-local-normalization.md).
